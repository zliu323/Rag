# 可复现的 RAG 评测

扩展集 `fixtures/qa_extended.json` 包含人工编写的 60 条虚构问题，其中 50 条有答案、10 条无答案。语料是 `sample_data/documents/` 的三份原始示例，以及 `fixtures/documents/` 的三份运维、数据治理、客户支持规范。每个有答案问题都标注了来源和原文证据、允许的关键词变体。运行前会检查证据确实存在。

这是项目内探索性评测集，未经独立人工复核，也没有独立留出的业务测试集。问答题由资料编写而来，不等于真实用户分布。请先冻结数据，再选参数；若根据这些题优化代码，应另建留出集验证。

## 本地运行

应用查询链路已新增词汇相关性初筛和结构化回答/拒答状态；原始 `results/offline.json`、`results/deepseek.json` 是修复前的冻结结果，没有覆盖或重新调用 API。`evaluation.suite` 仍用于直接对比检索和提供商的原始纯文本生成，未接入应用的相关性门控，不能作为修复后 `/query` 或 `/query/graph` 的效果报告。应用行为由 API 和图流程回归测试验证。

在项目根目录使用虚拟环境执行（Windows 可将 `python` 替换为 `.\.venv\Scripts\python.exe`）：

```bash
python -m evaluation.suite --output evaluation/results/offline.json
python -m pytest tests/test_evaluation_suite.py tests/test_metrics.py tests/test_hybrid.py
```

旧入口 `python -m evaluation.evaluate --lightweight` 和参数网格现已改为隔离的内存 FAISS，不加载持久化索引、不连接业务 pgvector、不发送业务追踪。旧入口生成答案时复用应用的初筛及结构化状态，默认使用本地生成；显式添加 `--llm deepseek` 才调用外部 API。可用 `python -m pytest tests/test_evaluation_isolation.py tests/test_graph_workflow.py tests/test_llm_usage.py tests/test_api.py` 验证隔离和拒答回归。

默认配置是 220 字符分块、40 字符重叠、Top-3；使用确定性 HashingEmbedder，无神经语义向量、无 Cross-Encoder。在相同语料和参数下比较纯向量与 BM25/RRF 混合检索，再使用本地抽取式生成器回答。独立内存索引不会加载或覆盖应用的 `data/index`。

`--k`、`--chunk-size`、`--overlap` 可调整配置。调整后的结果应写入不同文件；不能挑选最好的结果后宣称它代表未见业务数据的性能。

## DeepSeek 实际调用

项目 `.env` 已支持 `RAG_DEEPSEEK_API_KEY`、`RAG_DEEPSEEK_MODEL` 和 `RAG_DEEPSEEK_BASE_URL`，不应提交密钥。下面的命令会产生真实 API 请求和用量：

```bash
python -m evaluation.suite --llm deepseek --strategy hybrid --output reports/suite-deepseek.json
```

这一命令为 60 条题各生成一次答案，默认最多 3 个并发请求。请求发送至配置的 DeepSeek 接口，每次载荷包括项目的系统提示词、一个虚构问题及检索出的三个示例片段。不会发送 `.env` 文件或项目源码；API 密钥仅用于请求认证。当前配置地址为 `https://api.deepseek.com/chat/completions`，模型为 `deepseek-flash`。请求可能计费，实际金额按账户适用计费规则确定，报告记录提供商返回的输入/输出 Token 数，不估算金额。

首次连通测试可加 `--limit 1`。完整对比两个检索方案可使用 `--strategy both`，会调用 120 次。程序逐题保存答案、上下文、延迟与失败类型；中断后使用原参数、原输出路径并加 `--resume`，已成功问题不会重复调用，失败问题会重试。配置、代码或数据指纹变化时拒绝复用旧结果。

DeepSeek 在这里负责生成答案，检索仍使用同一个 HashingEmbedder。真实调用 DeepSeek 后，这仍是离线问答评测：问题来自固定测试集，不代表生产用户试运行。

用户明确批准发送范围后，已完成 60 次真实 DeepSeek 调用，全部成功。原始报告为 `results/deepseek.json`；`results/offline.json` 仍保留本地抽取式对照。详情与逐题拒答复核见 [results/deepseek-review.md](results/deepseek-review.md)。

## 指标口径

- Hit@3：有答案问题中，前三条至少含一个标注证据的比例。
- Evidence Recall@3：逐题计算被召回证据单元数/标注证据数，再对 50 题取平均。它与旧脚本的来源级 Recall 口径不同。
- All-evidence hit：所有标注证据均被检索到的问题比例，覆盖跨来源题。
- MRR：第一个命中标注证据的排名倒数，再取平均。
- 关键词覆盖率：每组允许变体至少出现一个的比例，先逐题计算再平均；它不能验证数字与条件的对应关系、语义正确性或幻觉。
- 拒答代理命中率：在 10 条无答案题中，用正则检查回答是否含“无法”“未提供”等表述；可能误判，需检查保留的逐题答案。
- 引用格式有效率：检查是否有 `[n]` 且编号在实际上下文范围内；它不能证明引用支持答案。

检索指标不混入无答案题；生成失败不记为零分，报告单列错误数和各指标分母。Token 用量只累计成功且返回用量的调用。该脚本的延迟是这次小规模运行的观测值，不是 API 压测吞吐量。

## 本次实测结果

完整原始结果见 `results/offline.json`，包含 120 条回答、原文上下文、代码/语料 SHA-256、环境信息和逐题分数。评测语料共 6 份文档、15 个非复制分块。

| 指标 | 纯向量 | BM25/RRF 混合检索 |
| --- | ---: | ---: |
| Hit@3（50题） | 98% | 100% |
| Evidence Recall@3（50题） | 97% | 100% |
| 全证据命中率（50题） | 96% | 100% |
| MRR（50题） | 0.9367 | 0.9867 |
| 抽取式关键词覆盖率（50题） | 96.33% | 98.33% |
| 无答案题拒答代理命中率（10题） | 0% | 0% |

按问题配对 bootstrap（固定种子 42，2,000 次重采样）的 Hit 差值 95% 区间为 [0, 6] 个百分点，证据召回差值区间为 [0, 8] 个百分点；均包含零。因此这里只能陈述这批题上的观测差异。MRR 差值为 0.05，区间约 [0.01, 0.0933]，也只适用于该合成集的重采样假设。

当前需要优先改善的缺陷是拒答：抽取式生成器在无关但有词汇重叠的上下文中仍会抽取句子。不能把它描述为可靠的企业问答正确率。

### DeepSeek 生成实测

保持同一混合检索配置，仅将生成器从本地抽取式切换为 DeepSeek，60 次调用全部成功：

| 指标 | 本地抽取式 + 混合检索 | DeepSeek + 混合检索 |
| --- | ---: | ---: |
| 关键词覆盖率（50题，代理指标） | 98.33% | 100% |
| 中文规则拒答命中率（10题，代理指标） | 0% | 90% |
| 引用编号格式有效率（50题） | 100% | 100% |

DeepSeek 生成耗时 P50 为 1.684 秒，P95 为 1.980 秒；输入 Token 总计 29,786，输出 Token 总计 2,047。该结果是 3 并发、小样本问答实验的观测值，生成时间包含网络等待，不是服务容量或生产 SLA。

AI 助手逐题复核了全部 10 条无答案题：10 条均明确指出资料未提供所问信息。其中 `unknown10` 使用英文表达“上下文未指定登录密码”，被只检查中文的原始正则漏判。自动评分保留为 90%，不回改评分规则；这次复核是对已知测试结果的事后检查，不能作为独立人工评测。另记录该题回答语言与中文提问不一致的缺陷。

检索指标与本地混合检索一致，因为 DeepSeek 仅负责生成。100% 的关键词覆盖与编号有效不等于完整语义正确率，也不能据此宣称生产问题零幻觉。

如需在简历中体现真实 API 验证，可补充：

> 接入 DeepSeek 完成 60 条合成问题的端到端离线验证，记录逐题答案、引用上下文及 Token 用量；50 条有答案题关键词覆盖率达 100%，生成延迟 P95 为 1.98 秒，并通过无答案测试定位拒答评分的跨语言漏判。

简历可采用保守表述：

> 构建含 50 条可回答、10 条无答案问题的可复现离线评测集，建立证据级召回、MRR、答案关键词覆盖及拒答检查；在轻量哈希向量基线上对比 BM25/RRF 混合检索，测试集 Hit@3 从 98% 提升至 100%，MRR 从 0.9367 提升至 0.9867，并保留逐题证据和失败样本。

此前通过复制示例到 6,000 片段得到的负载结果，属于重复语料的合成微基准。关闭 BM25 后更快是不同工作量之间的对比，不能依据四条 QA 指标持平，将其写成普遍适用的“效果不变、性能优化98.4%”。
